# CLAUDE.md — lib/models/

Plain data classes. No Flutter imports, no I/O, no state. Each model owns
its own JSON codec because we persist to SharedPreferences as strings.

## Files

| File | Purpose |
| --- | --- |
| `user_profile.dart` | `UserProfile` (anonymous UUID + optional demographics) and `Gender` enum |
| `sensor_sample.dart` | One IMU row (10 fields) + CSV header constant + `toCsvRow()` |
| `session.dart` | `SessionMetadata` (index entry pointing at a CSV on disk) |

## Persistence contract

- **All three models are stored as JSON strings** — `UserProfile` and
  `SessionMetadata` in SharedPreferences, `SensorSample` never persisted as
  JSON (it becomes a CSV row). `encode()` / `decode()` are symmetric.
- **`SessionMetadata` is stored inside a `StringList`** (the sessions
  index). Each list entry is one encoded metadata JSON.
- **Corrupt entries are silently skipped** on read
  (`storage_service.dart:145-151`, `78-86`). Don't add throwing paths —
  the app must survive partial corruption without a crash loop.
- **All dates use ISO-8601 with timezone** (`DateTime.toIso8601String()`).
  Reading uses `DateTime.parse`, which preserves the timezone offset. The
  backend expects UTC — `HarApi` calls `.toUtc()` explicitly on upload.

## Field-typing conventions

- **UUIDs are stored as `String`, not typed IDs.** They're generated by
  `package:uuid` on the client and passed to the backend verbatim.
- **`SessionMetadata.relativePath`** is relative to the app documents
  directory (`sessions/<uuid>.csv`), never absolute. Full path is resolved
  on demand via `StorageService.sessionFileFullPath(relative)`. Storing
  relative paths keeps the index portable across iOS reinstalls that change
  the sandbox path.
- **`UserProfile.heightCm` and `weightKg` are `double?`.** The backend
  stores them as integers, so the API client rounds on the way out
  (`har_api.dart:63-64`). Don't lose precision in the app itself.
- **`SessionMetadata.description` is `String?`**, and empty strings are
  normalized to `null` at the call-site (`home_screen.dart:161`,
  `har_api.dart:96`).

## CSV row contract (`SensorSample`)

```
csvHeader = [
  'timestamp_ms', 'accel_x','accel_y','accel_z',
  'gyro_x','gyro_y','gyro_z','mag_x','mag_y','mag_z'
]
toCsvRow() = '$timestampMs,$accelX,$accelY,$accelZ,...'
```

If you add or reorder a field:

1. Update `csvHeader`.
2. Update `toCsvRow`.
3. Update `SessionWriter.open` — it writes the header line from the same
   constant, so the header stays in sync automatically. Rows won't.
4. Coordinate with the backend if the schema is user-facing (columns are
   opaque to the backend today — it stores bytes — but pandas consumers
   will break).

## copyWith pattern

`UserProfile.copyWith` and `SessionMetadata.copyWith` are the only mutation
paths. Both use the standard `field ?? this.field` idiom. Note this means
you **cannot use `copyWith` to null a field back out** — pass a fresh
constructor call for that. Today only non-null updates happen, so this is
fine; be aware if you add "clear" flows.
